# Issues

- For a bug, explain the impact, workflow, observed and expected behavior, environment, and reproducible steps or other verified evidence. For a proposal, explain the problem, desired outcome, scope and context. Give either issue a specific title and objective acceptance criteria.
- Mark assumptions and missing facts explicitly. State genuine blocking dependencies, link verified related issues and omit empty optional sections. Use labels, templates, assignees and milestones after verifying that they exist and apply.
- Apply the [privacy rule](safety-git.md#private-data-and-fixtures) to issue examples and findings. Use an authorized private channel for sensitive findings.

Use the [create issue workflow](workflow-review.md) to prepare or publish an issue and [start issue](workflow-review.md) to implement one.
