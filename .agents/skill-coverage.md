# Bear Studio Web skill coverage

This audit used application routes and source, migration and test files, dependency manifests and locks, shipped asset notices, CI and hosting instructions. The versions below describe this checkout. For an upgrade, check the corresponding manifest, lock, bundle or runner configuration again. A library merits its own skill when it has a recurring project task that the existing guidance does not cover.

| Area and evidence | Coverage and decision |
| --- | --- |
| **PHP and Laravel.** PHP 8.4, Laravel 13, Artisan, Blade, routing, validation, Laravel sessions and cache, Query Builder. The application separates public rendering and editorial reads from management writes for projects, services, Home, FAQs, articles, categories, settings, users and roles. See [Composer manifest](../composer.json), [routes](../routes/web.php) and [design](../docs/design.md). | `laravel-best-practices` owns framework guidance. Keep feature behavior in the design and code. Laravel Cloud, Sail, Eloquent-first and panel React workflows have different assumptions. |
| **Application security and media.** Host separation, custom cookie and CSRF flow, permission and role checks, audit, PHP password APIs, HTML handling via DOM, GD/WebP images, Fileinfo, MP4 validation, private storage, delivery and cleanup. | Laravel's [security guidance](skills/laravel-best-practices/rules/security.md), project [lifecycle rules](rules/data-lifecycle.md), tests and [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/) cover defensive review. OpenAI's [framework-specific security skill](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431/skills/.curated/security-best-practices) has no PHP/Laravel references. A media editor or transcoding skill would not cover the PHP upload and storage workflow. |
| **MariaDB.** MariaDB 10.11 CI baseline, PDO MySQL, InnoDB, schema upgrades, foreign keys, shared write lock and concurrent state changes. See [database config](../config/database.php) and [CI](../.github/workflows/ci.yml). | Keep `mariadb-features` and `mariadb-query-optimization`. The other [official MariaDB skills](https://github.com/MariaDB/skills) cover unused workflows such as MCP, replication, vector search, temporal tables or migration from a different engine. For hosting backup and restore, use the deployment guide and [MariaDB backup documentation](https://mariadb.com/docs/server/server-usage/backup-and-restore). |
| **API and developer documentation.** OpenAPI 3.0.3, Swagger UI 5.36.0 in local development, League OpenAPI PSR-7 Validator and Nyholm PSR-7 in tests. The same [JSON contract](../docs/openapi.json) is available for import into compatible tools. | Add `update-api-contract` for the Laravel, OpenAPI and panel compatibility workflow. [Swagger UI upstream skills](https://github.com/swagger-api/swagger-ui/tree/master/.claude/skills) focus on maintaining Swagger UI itself. [Bruno skills](https://github.com/bruno-collections/bruno-agent-skills) focus on collections and CLI workflows. [Redocly tooling](https://github.com/Redocly/redocly-plugin) and [Speakeasy skills](https://github.com/speakeasy-api/skills) assume tools outside this checkout. Keep the single spec and the existing PHP validation path. |
| **PHP testing and code quality.** PHPUnit 13, Mockery as a dev dependency, coverage tooling, Larastan 3/PHPStan 2, Pint and Composer validation/audit. See [test guide](../docs/testing.md). | `validate-web` owns isolated checks and [Laravel Boost testing-best-practices](skills/testing-best-practices/SKILL.md) supplies PHPUnit design guidance. `laravel-tdd` remains an optional reference. [PHPStan's published skill](https://github.com/phpstan/phpstan/blob/c3874c8035d039a5ead6f9206cd758af23725765/.claude/skills/analyse-with-phpstan/SKILL.md) uses its public playground API. The project's local `composer analyse` applies its Larastan configuration and keeps source local. |
| **Composer dependencies.** The [lock](../composer.lock) records 74 production and 45 development packages. Laravel transitives include Symfony components, Carbon, Flysystem, Monolog, Guzzle and PSR interfaces. Test and analysis transitives include Sebastian components, PHP-Parser, Hamcrest, schema parsing and coverage helpers. Symfony is used directly in a few seams such as binary responses and console input. | Treat the lock as inventory and use the owning Laravel or test workflow for shared behavior. Consult the package's own reference for a component-specific change. A Symfony framework, HTTP client, logger, storage or parser pack would expand coverage beyond the actual maintenance tasks here. |
| **Public site assets.** Blade, HTML/CSS and browser APIs, shipped Tailwind 4.3.3 CSS, bundled vanilla Motion with Motion DOM/Utils and Framer Motion notices, Inter variable font, WebP/MP4 presentation and SEO metadata, sitemap and robots. Asset versions and licenses are separate from npm development tooling. | Add the [official Motion skill](https://motion.dev/docs/ai-kit-install) for its offline vanilla JS guidance. Keep existing Tailwind, platform, design, accessibility, UI review, SEO and performance skills. React/Vue, premium Motion workflows, separate typography skills and duplicate CSS or accessibility packs add no current workflow. The Motion bundle has no verified semantic version in the checked source. |
| **Browser tests and Node tooling.** Node 24, npm, Playwright 1.65.1, TypeScript 7.0.2, Node types 24.19.4, Swagger UI distribution and their lock entries for Playwright core, optional compiler binaries, Undici types and Scarf. See [npm manifest](../package.json), [lock](../package-lock.json) and [Playwright config](../playwright.config.ts). | `playwright-cli` and `validate-web` cover current workflows. Use the configured typecheck for the browser tests and configuration. [Microsoft's TypeScript skills](https://github.com/microsoft/typescript-skills) are available for migrations or advanced compiler setup. The checked updater guides the 6-to-7 upgrade, which this checkout already uses. A second browser or Chrome performance skill would duplicate the current workflow. |
| **GitHub Actions and Dependabot.** SHA-pinned actions, Linux jobs, MariaDB test service, quality/coverage/browser/release evidence, and weekly Composer, npm and action updates. See [workflow](../.github/workflows/ci.yml) and [Dependabot](../.github/dependabot.yml). | Add [github-actions-hardening](https://github.com/github/awesome-copilot/tree/93fc8b9ee3ef56b9b5e7261e6ce92d314cb2c1cf/skills/github-actions-hardening) for workflow security and [dependabot](https://github.com/github/awesome-copilot/tree/93fc8b9ee3ef56b9b5e7261e6ce92d314cb2c1cf/skills/dependabot) for update policy. `review-pr`, `gh-fix-ci` and `yeet` own separate review, diagnosis and publication workflows. The [OpenAI review-comment skill](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431/skills/.curated/gh-address-comments) adds little to the existing PR thread rules and depends on an elevated CLI workflow. |
| **Release and hosting.** PHP/Composer production package, Apache rewrites, Linux DirectAdmin hosting, separate public and admin origins, private storage and database. The MariaDB image is a CI service. See [deployment](../DEPLOY.md) and [DirectAdmin installation](../deploy/full-site/INSTALL.md). | The project runbook and [DirectAdmin Apache docs](https://docs.directadmin.com/webservices/apache/index.html) cover the current deployment. Use [verify-release](skills/verify-release/SKILL.md) for package identity, deployment smoke checks and recovery. Vercel, container deployment and Laravel Cloud skills assume other infrastructure. |

Third-party source folders are pinned in the [source manifest](skills-sources.json). The Motion AI Kit repository has no standalone license file at the installed revision. Its [preserved upstream package manifest](skills/motion/UPSTREAM-PACKAGE.json) and [publisher's install documentation](https://motion.dev/docs/ai-kit-install) identify the skill's MIT license. Keep existing snapshots intact. Use the [selection table](README.md#select-a-skill) to limit overlap when tasks touch multiple areas.
